# 隐私保护知识问答：让敏感信息止步于知识库

## 1. 案例简介

本案例演示如何用 agentUniverse 搭建一个"先脱敏、再检索、后作答"的客服工单问答智能体。知识库中的工单包含虚构的邮箱、手机号、银行卡、身份证号与工号；通过 DocProcessor 管道在入库前完成脱敏，召回时再做兜底清洗，保证敏感原文不会进入大模型上下文，同时每篇文档保留脱敏统计（redaction_summary）用于合规审计。

适合场景：客服工单问答、HR 内部知识库、医疗/金融等对隐私敏感的内部问答。

## 2. 前置准备

1. 已完成 agentUniverse 环境部署
2. 仅在线问答步骤需要大模型 API Key（检索链路可完全离线验证）

## 3. 核心设计

```
support_tickets.txt
   │  default_txt_reader
   ▼
recursive_character_text_splitter   ← 切分为可检索片段
   ▼
ticket_redactor                     ← 入库脱敏（内置实体 + 自定义工号/订单号正则）
   ▼
privacy_sqlite_store                ← BM25 存储（SQLite + jieba，零密钥）
   │
   │ 查询时
   ▼
recall_redactor                     ← 召回兜底脱敏（log_key: null，不覆盖入库统计）
   ▼
privacy_guard_agent                 ← 仅依据已脱敏背景作答
```

关键配置 `intelligence/agentic/knowledge/privacy_knowledge.yaml`：

```yaml
stores:
    - 'privacy_sqlite_store'
insert_processors:
    - 'recursive_character_text_splitter'
    - 'ticket_redactor'
post_processors:
    - 'recall_redactor'
```

自定义脱敏规则示例 `doc_processor/ticket_redactor.yaml`：

```yaml
entities: [email, phone, credit_card, id_card, ip_address]
custom_patterns:
    - name: employee_id
      pattern: '\bEMP-\d{6}\b'
    - name: order_no
      pattern: '\bORD-\d{8}\b'
log_key: 'redaction_summary'
```

## 4. 运行

```bash

# 离线验证：插入样例工单并检索，断言无任何 PII 泄漏（无需密钥）
python intelligence/test/privacy_pipeline_test.py
# 预期输出: OK: N documents retrieved, all PII redacted.
#          Sample redaction summary: {'email': 1, 'phone': 1, 'credit_card': 1, ...}

# 在线问答（可选）
cp config/custom_key.toml.sample config/custom_key.toml   # 填入 DEEPSEEK_API_KEY

```

向智能体提问示例：`退款一般多久到账？银行卡会怎么处理？`——回答只会引用已脱敏内容与工单编号，联系方式一律为 [REDACTED]。

## 5. 原理说明

- 内置实体（邮箱/手机/卡号/身份证/IP 等）带结构校验：卡号需通过 Luhn 校验、身份证号需通过 GB11643 校验，避免把普通数字串误伤成敏感信息。样例数据使用的是结构合法的虚构号码。
- `log_key: null` 时召回侧处理器不写统计信息，从而保留入库时记录的 redaction_summary，两者配合实现"双重清洗 + 单次统计"。
- 检索默认使用 SQLiteStore（BM25 + jieba 分词），无需向量模型即可离线运行；如需语义检索，新增 Chroma/FAISS store yaml 并加入 stores 列表即可，参考 rag_app。

## 6. 常见问题

1. 检索不到内容：确认已在应用根目录运行（db_path 为相对路径），或删除 `intelligence/db/privacy_store.db` 后重新插入。
2. 某些号码未被脱敏：内置卡号/身份证规则要求结构合法（Luhn/GB11643），演示数据请使用校验合法的虚构号码；业务专用编号请配置 custom_patterns。
3. 在线问答报密钥错误：检查 `config/custom_key.toml` 中 DEEPSEEK_API_KEY 是否有效。
